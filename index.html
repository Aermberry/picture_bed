yigecli 工程架构与功能详细设计

面向日常写作与 Agent 协作：扫描文件夹中的 Markdown / HTML 等文档，抽取内嵌图片， 经 PicX 同款 GitHub 图床通道上传，再自动回写稳定链接。本阶段只做设计，不实现业务功能。

状态：设计评审稿 形态：CLI only 图床：GitHub Contents API（PicX 兼容） 日期：2026-09-22

1. 背景与目标

日常开发中常用 picx-app 的 Web/桌面端作为图床。其能力核心是基于 GitHub API 的图片上传托管与链接生成。 现有不足：

  • 难以对一整篇/一整夹文档里内嵌的本地图片做批量处理；
  • 流程偏 GUI，Agent / 脚本难以稳定驱动（缺少可脚本化的 CLI 契约）。

因此本仓库（picture_bed）规划本地工具 yigecli（「一个 CLI」）：

  1. 读取目录下 Markdown、HTML 等文档中的内嵌图片引用；
  2. 将本地图片自动上传至图床（PicX 同源 GitHub 通道）；
  3. 自动把文档中的链接替换为可公开访问的稳定 URL。
设计原则：可组合、可预览（dry-run）、可回滚（manifest）、可被 Agent 无歧义调用（JSON / 退出码 / 无交互默认）。

2. 范围与非目标

2.1 v1 范围（Must）

  • CLI 可执行文件 yigecli（Windows / macOS / Linux）
  • 目录扫描 + 文档解析：Markdown、HTML（含常见图片语法）
  • 本地图片解析（相对/绝对路径）、内容哈希去重
  • GitHub Contents API 上传（与 PicX 图床模型对齐）
  • 链接回写（原地替换或输出到 out-dir），支持 dry-run
  • 人机双模式：默认人类可读输出 + --json 机器可读
  • 本地配置与 token 从环境变量/配置文件读取（不入库）
  • manifest 记录映射，支持幂等重跑与 revert

2.2 明确非目标（v1 Must Not）

  • 不做 Web UI / Tauri 桌面壳（picx-app 已覆盖 GUI）
  • 不实现 GitHub OAuth App 流程（沿用 PAT / 环境变量；OAuth 留给后续）
  • 不做图片压缩/水印/智能裁剪工具箱
  • 不托管非图片二进制（PDF、视频等）作为 v1 目标
  • 不替代 Git LFS 或对象存储；仅走 GitHub 图床通道

2.3 后续候选（Backlog）

  • VS Code / Agent MCP 包装、监听 watch 模式
  • 多图床适配器（S3、又拍、自定义 HTTP）
  • 自动 PR / 删除远端冗余对象的清理策略

3. 用户与 Agent 场景

开发者（人）

在写作目录执行 yigecli sync ./docs，预览将上传的图片与替换表，确认后写入文档。

Agent / CI

调用 yigecli sync --json --yes，解析 stdout JSON，依据退出码决定重试或失败；无 TTY 交互。

维护者

用 yigecli doctor / yigecli config 检查 token、仓库与 CDN 规则是否可用。

4. 总体架构

采用「管道 + 适配器」分层，核心域与 I/O 严格分离，便于单测与 Agent 契约测试。

4.1 建议技术栈

  • 语言：TypeScript + Node.js ≥ 20 — 与 PicX 前端生态同源，解析 MD/HTML 库成熟，便于 Agent 安装（npm/npx）。
  • CLI：commander / citty；校验：zod；HTTP：undici；MD：自研轻量扫描 + unified/remark（可选）。
  • 测试：vitest + fixture 目录；打包：可选 nexe/pkg 或直接 npm bin。

备选：Go（单二进制分发更强）；若强调无 Node 依赖的 Agent 环境可切换。v1 默认 Node/TS。

5. 模块详细设计

模块职责关键接口（示意）
cli/ 参数解析、子命令编排、输出格式化、退出码 run(argv): Promise<ExitCode>
core/scan 目录遍历、扩展名过滤、忽略规则 scanDocs(root, opts): DocFile[]
core/parse MD/HTML 图片引用抽取（含 srcset、<img>、![]()、<image>） extractRefs(doc): ImageRef[]
core/resolve 路径解析、存在性/类型校验、哈希、去重图 resolveAssets(refs): AssetGraph
core/plan 生成上传计划：skip/upload/relink buildPlan(graph, cache): SyncPlan
core/rewrite 按语法安全替换链接，保留周边空白/转义 rewriteDoc(doc, map): string
core/manifest 本地映射持久化、幂等、revert ManifestStore.load/save
host/github Contents API 上传/存在查询；CDN URL 生成 upload(asset): RemoteImage
host/types 图床适配器接口（为多后端预留） interface HostAdapter
config/ 配置加载合并：CLI > ENV > 项目文件 > 用户文件 loadConfig(): ResolvedConfig

5.1 核心数据模型

type DocKind = 'markdown' | 'html';

interface ImageRef {
  docPath: string;
  raw: string;
  start: number;
  end: number;
  kind: DocKind;
  syntax: 'md-image' | 'md-link' | 'html-img' | 'html-srcset' | 'html-source' | 'other';
  alt?: string;
}

interface Asset {
  localPath: string;
  sha256: string;
  bytes: number;
  mime: string;
  refs: ImageRef[];
}

interface RemoteImage {
  publicUrl: string;
  rawUrl: string;
  cdnUrl?: string;
  repoPath: string;
  sha256: string;
}

interface SyncPlanItem {
  action: 'upload' | 'skip-cache' | 'skip-remote' | 'rewrite-only' | 'blocked';
  asset?: Asset;
  remote?: RemoteImage;
  reason?: string;
}

interface SyncResult {
  ok: boolean;
  uploaded: number;
  rewrittenDocs: string[];
  mapping: Record<string, string>;
  warnings: string[];
  errors: string[];
}

6. CLI 命令面

命名：可执行名 yigecli；全局选项在所有子命令前可用。

命令作用关键选项
yigecli init 生成 yigecli.toml 模板与 .gitignore 条目提示 --force
yigecli doctor 检查 token、仓库权限、API 连通、配置完整性 --json
yigecli scan <path> 只扫描解析，列出文档与图片引用（不上传） --ext md,html --json
yigecli plan <path> 生成同步计划（upload/skip），等价 dry-run 的 plan 报告 --json
yigecli sync <path> 上传图片并回写文档 --dry-run --yes --out-dir --json
yigecli upload <file> 单文件上传，仅输出 URL --json
yigecli revert <path> 按 manifest 将文档链接恢复为本地路径 --dry-run
yigecli config get|set|list 查看/修改项目配置（token 只显示掩码） --json

6.1 示例

# 人类可读预览
yigecli plan ./docs

# Agent / 脚本
yigecli sync ./docs --json --yes

全局选项：--json、--quiet、--verbose、--config <file>、--cwd <dir>、--yes（跳过确认，Agent 默认建议显式传入）。

7. 文档解析与图片抽取

7.1 支持格式（v1）

  • Markdown：![alt](path)、指向图片扩展名的链接、内嵌 <img>
  • HTML：<img src|srcset>、<source src|srcset>、<image href>（SVG）
  • 扩展名白名单：png,jpg,jpeg,gif,webp,avif,svg,bmp,ico（可配置）

7.2 路径解析规则

  1. 相对路径相对于文档所在目录解析；
  2. file:// 与绝对路径：默认拒绝（可 --allow-absolute）；
  3. 已是 http(s):// 的远程链接：默认 skip（--reupload-remote 可选）；
  4. 锚点、数据 URI：skip；data URI v1 可 --inline-data-uri 落盘后再传。

7.3 抽取策略

  • 两阶段：轻量扫描定位候选 → 语法上下文校验，避免代码块内 ![]() 误伤；
  • 记录精确 start/end 偏移，回写用切片替换而非全文正则；
  • 同一文件多引用同一资源：一次上传，多处替换。

8. 上传与 PicX / GitHub API

PicX 图床本质是 GitHub 仓库文件托管。yigecli 的 host/github 对齐该模型，而不是调用 picx-app 的私有前端逻辑。

8.1 配置对齐 PicX 概念

PicX 概念yigecli 配置键说明
Tokengithub.token / YIGE_GITHUB_TOKENPAT，repo 或 fine-grained Contents RW
Ownergithub.owner用户或组织
Repogithub.repo图床仓库名
Branchgithub.branch默认 main
目录github.dir如 img 或 assets/blog
CDN 规则url.styleraw | jsdelivr | custom

8.2 上传流程

  1. 计算 sha256，查本地 manifest/cache：命中且 URL 仍可用 → skip-cache；
  2. 确定远端路径：{dir}/{yyyy}/{mm}/{sha12}-{safeName}（可配置模板，保证幂等）；
  3. 调用 GitHub REST： GET /repos/{owner}/{repo}/contents/{path} 探测； PUT /repos/{owner}/{repo}/contents/{path} 提交 {message, content: base64, branch}；
  4. 按 url.style 生成公开 URL 并写回。

8.3 URL 样式

# raw
https://raw.githubusercontent.com/{owner}/{repo}/{branch}/{path}

# jsdelivr（PicX 常用）
https://cdn.jsdelivr.net/gh/{owner}/{repo}@{branch}/{path}

# custom
https://cdn.example.com/{path}

8.4 约束与限流

  • 并发默认 2–3，对 403/429 指数退避；
  • 单文件建议 ≤ 50MB（GitHub 常用上限）；
  • commit message 可配置，默认 chore(yigecli): upload N images。

9. 链接回写

  • 默认原地替换；--out-dir 时写副本，原文件不动；
  • 替换仅覆盖引用的 URL 部分，保留 alt、title、srcset 其它候选；
  • 写入前生成 .yigecli/backup/ 备份（可用 --no-backup 关闭）；
  • 原子写：临时文件 + rename；
  • 编码保持 UTF-8，检测 BOM 差异并警告。

9.1 Manifest（.yigecli/manifest.json）

{
  "version": 1,
  "entries": [{
    "doc": "docs/post.md",
    "localPath": "docs/assets/a.png",
    "sha256": "…",
    "publicUrl": "https://cdn.jsdelivr.net/gh/…",
    "raw": "./assets/a.png",
    "updatedAt": "2026-09-22T00:00:00Z"
  }]
}

用途：幂等跳过、revert、审计、Agent 断点续跑。manifest 不包含 token。

10. 配置与密钥

10.1 优先级

CLI flags > ENV > ./yigecli.toml > ./.yigecli/config.toml > 用户级配置

10.2 示例 yigecli.toml

[github]
owner = "Aermberry"
repo = "pic-bed"
branch = "main"
dir = "img"
# token 请用环境变量 YIGE_GITHUB_TOKEN

[url]
style = "jsdelivr"   # raw | jsdelivr | custom

[scan]
extensions = ["png", "jpg", "jpeg", "gif", "webp", "svg"]
ignore = ["**/node_modules/**", "**/.git/**"]

[upload]
concurrency = 3
commit_message = "chore(yigecli): upload images"

[rewrite]
backup = true

10.3 密钥纪律

  • Token 只来自 ENV 或本地用户配置；禁止写入仓库文件、manifest、日志；
  • config list 输出掩码；
  • .yigecli/ 中 backup/manifest 默认建议 gitignore。

11. Agent 友好接口

  • 无交互默认：非 TTY 时不弹确认，需写文件的命令要求显式 --yes 或 --dry-run
  • 稳定 JSON Schema：所有命令 --json 输出 JSON，字段版本化（schemaVersion）
  • 纯退出码：Agent 可不解析正文只看 exit code
  • 幂等：重复 sync 不重复上传同一 sha256
  • 可脚本发现：yigecli --help / yigecli commands --json
  • 日志可关：--quiet 时 stdout 仅 JSON；诊断走 stderr

11.1 建议的 Agent 调用序列

yigecli doctor --json
yigecli plan ./docs --json
yigecli sync ./docs --json --yes
yigecli revert ./docs --dry-run --json

12. 错误模型与退出码

Code含义典型场景
0成功全部处理完成（含 0 变更）
1通用失败未分类错误
2用法错误参数不合法
3配置/鉴权缺 token、权限不足
4本地文件图片缺失、路径越界
5远端 API4xx/5xx、限流耗尽
6部分成功部分文档回写失败
7需要确认无 --yes 且将修改文件

错误 JSON 形状：{ ok:false, code:"E_UPLOAD", message, path?, hint? }，禁止把 secret 打进 message。

13. 测试与验证策略

对齐项目规则：每次改动必须有相关测试，交付前全部通过。设计阶段交付物为文档，验证规则见下；实现阶段按下表落地。

层手段要点
单元vitestparse/rewrite/resolve/plan 纯函数；fixture 黄金文件
契约mock HTTPGitHub Contents 请求形状、幂等、退避
CLIspawn 集成退出码、--json schema、无 TTY 行为
端到端本地假图床fixture：md+html+图片 → sync → 断言文档与 manifest
设计文档（本阶段）scripts/validate-design.ps1index.html 关键锚点/章节完整性
  • 黄金用例：代码块中的 ![]() 不被改写；中文路径；同一图多引用；已有 URL 跳过。
  • 「不能失败的检查不算证明」：新检查需先在已知坏输入上失败再采信。

14. 里程碑与交付

  1. M0 设计冻结（本交付）：架构/命令/契约评审通过 → 实现排期
  2. M1 骨架：init/doctor/config + 配置加载 + 单测
  3. M2 抽取：scan/plan + MD/HTML 解析 + fixture 测试
  4. M3 上传：upload/sync + GitHub adapter + 幂等 cache
  5. M4 回写：rewrite + backup + revert + e2e
  6. M5 打磨：JSON schema 冻结、文档、npm 发布

每个里程碑结束：全量测试通过 + 对应 git commit（遵守项目交付规则）。

15. 风险与开放问题

GitHub 限流 / 大文件

图床仓库膨胀与 API 配额。缓解：hash 去重、并发限制、CDN 缓存说明。

解析误伤

MD 代码块、转义括号。缓解：偏移替换 + 黄金测试；极端语法 warning。

「该项目的 API」语义

picx-app 无独立公网 OpenAPI，能力即 GitHub API + URL 约定。若后续发现私有接口再适配。
